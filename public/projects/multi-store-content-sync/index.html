Multi-store content sync

An admin app that keeps content in sync across a client's multiple stores: metaobjects, metafields, menus, blogs, pages and translations. Deployed as a separate instance per client and built by a team of four developers.

An internal tool at aiconomy AG, built while I worked there as a developer. The details below describe my part.

Work with me
Company
aiconomy AG
My role
Developer
Stack
React Router, TypeScript, Prisma, Admin GraphQL API, Polaris

My contribution

  • Metaobject synchronisation: reserved Shopify types are checked for existence rather than created, definition validations are remapped against the target store, and referenced file IDs are mapped so images survive the transfer.
  • Blog metafields sync as a new route and UI, with deduplicated error summaries that expand to full detail.
  • Theme-referenced file backfill: enumerating a store's whole file library was timing out, so the app resolves only the files the live theme references and uploads those missing on the target, as a scheduled background job.
  • Exact-filename matching on file lookup, so naming collisions no longer upload the wrong asset.
  • Market adaptation, so each target store receives translations in its own primary language.
